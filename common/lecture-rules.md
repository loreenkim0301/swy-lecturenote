# 교안 작성 규칙서

2026-10-15 · Loreen kim

10/19·10/22 SKT KHP 보고서/기획서 교안을 만들며 로린님이 고치거나 지시한 방향을 모은 규칙이에요. 다음 교안부터 이 순서로 점검해요.

- 원본(편집용) 문서: https://claude.ai/code/artifact/dde57d00-d12c-46b2-8658-826e98141c38
- 이 파일은 저장소 공통 문서예요. 규칙이 바뀌면 원본 문서와 이 파일을 함께 고쳐요.

## 1. 문구와 톤

교안 본문은 학생에게 하는 안내 문장으로만 써요. 만든 사람에게 남기는 메모나 테스트 보고 투는 넣지 않아요.

| 구분 | 규칙 | 예시 |
| --- | --- | --- |
| 지울 것 | 테스트 결과를 보고하는 문장 | "회의록 템플릿은 보이지 않아요", "실제로 돌려 보니 ~였어요", "25분 넘게 멈췄어요" |
| 바꿔 쓸 것 | 관찰한 현상은 학생이 확인할 점으로 | "~인지 확인해요", "~할 수 있어요" |
| 남길 것 | 실행 화면의 날짜·계정 표기 | "(2026년 10월 15일 Plus 계정 실제 실행 화면)" |
| 남길 것 | 실습 사용량 기록 | "크레딧 0, 주간 무료 할당량 21% 사용 (2026-10-15 기준)" |
| 남길 것 | 공식 출처의 확인일·갱신일 | "· 2026-10-15 확인", "(2026-09-24 갱신)" — 최신성을 보여 줌 |

- 대상은 교육과정마다 다르므로 대상 확인 필요
- 사용 가능 툴과 사용 불가 툴은 교육과정마다 다르므로 확인 필요
- 버튼·메뉴 이름은 화면에 보이는 그대로 [ ]로 적어요. 예: [보기 및 내보내기], [내 문서]
- 사람 이름이 들어가는 곳은 강사 실명(김**)을 써요.
- 강사의 개인정보가 표시되는 부분은 마스킹해요.

## 2. 근거와 검증

출처를 두 번 확인하지 않은 내용은 교안에 쓰지 않아요. 도구의 기능은 공식 가이드와 실제 실행 화면 둘 다로 확인해요.

1. 기능 설명은 공식 가이드(Help Center)를 먼저 찾고, 근거는 참고 박스에 링크와 확인일로 남겨요.
2. 실습 프롬프트는 실제 계정에서 실습 파일로 돌려 본 뒤에 넣어요.
3. 공식 가이드에 없는 기능은 본문 실습에서 빼고, "공식으로 제공하는 것"을 참고 박스로 안내해요. 예: HWP·HWPX 내보내기 삭제 → Word·PDF·Markdown, XLSX 안내
4. 공식 가이드와 실제 화면이 다르면 실제 화면에서 되는 방법으로 실습을 짜고, 차이는 참고 박스에 적어요. 예: 사본 만들기 대신 "새 파일을 따로 만들어 줘"
5. 오래 멈추는 기능은 실습 경로에서 빼고 되는 경로로 바꿔요. 예: AI 시트 차트 → 홈 입력창
6. 파일 구조만 확인하고 실제 프로그램에서 열어 보지 않은 결과는 "확인되지 않음"으로 구분해요.
7. 조사가 수집되지 않았으면 있는 척 정리하지 않고, 모인 것이 없다고 그대로 알려요.

## 3. 구성

뼈대는 고객사 커리큘럼, 내용은 우리가 검증한 실습 예시와 흐름으로 채워요.

- 고객사가 준 커리큘럼 표를 찾아 교안과 대조하고, 커리큘럼 키워드가 빠진 곳이 없는지 확인해요.
- 기준 도구는 유료 버전(강사 계정)으로 하되, 학생 계정 제공 여부는 고객사에 확인해요.
- 모두 같은 설정으로 맞추는 단계(모델·모드)는 교안 맨 앞에 둬요.
- 도입은 워크플로우 스케치(내 업무 쓰기 → 단계로 쪼개기)로 시작해요.
- 같은 주제를 다른 교안에서 다뤘다면 더 최근 교안의 내용을 써요. 예: 차트 만들기는 10/14 교안 기준
- 시간이 모자라면 부차적인 파트는 삭제해요. 예: 정리 규칙서·검증용 보고서 파트 삭제
- 수강 기관에서 쓸 수 없는 도구는 표현까지 본문에서 빼요. 예: Microsoft 365·엑셀
- 기능 안내는 "찾기 → 채우기 → 만들기 → 저장 → 불러와 쓰기"처럼 실무 워크플로우 순서로 엮어요.

## 4. 실습과 프롬프트

프롬프트는 복사해서 바로 쓸 수 있게 넣고, 결과는 내 자료나 기준값과 대조하게 해요.

- 프롬프트는 복사 박스에 **요청 / 내용 / 형식** 3줄로 써요.
- 바꿔 넣을 자리는 [ ]로 비워요.
- 자료에 없는 칸은 [확인 필요]로 남기라고 프롬프트에 넣어요.
- AI가 없는 내용을 덧붙이는 지점(할 일, 연도, 숫자)은 "~는 추가하지 마"를 프롬프트에 넣고, 결과 확인 항목으로도 안내해요.
- 데이터 실습에는 기준값 표를 바로 달고, "숫자가 다르면 무엇을 물어볼지"까지 써요.
- 실습마다 결과 확인 체크리스트를 두어요.
- 실습 데이터는 가상 회사(셀렉트마켓) 예시를 쓰고, 실제 업무 자료는 가상 값으로 바꿔 올리라고 안내해요.
- 크레딧이 드는 작업은 미리 알리고, 기본은 무료 할당량으로 되는 설정(표준 모드)으로 짜요.

## 5. 화면 캡처

캡처는 실제 계정으로 실습을 돌리며 찍고, 해당 단계 바로 아래 넣어요.

- 단계마다 "어디를 누르는지"가 보이는 화면과 "결과"가 보이는 화면을 찍어요.
- AI가 틀린 부분이 드러나는 화면도 넣고, 설명에는 학생이 확인할 점을 써요.
- 캡션은 학생용 안내 문장으로 쓰되, 실행 날짜·계정 표기는 남겨요(1장 표 참고).
- 이미지는 대체 텍스트(alt)에 화면 내용을 적고, 없어도 되는 캡처(막힌 경로, 쓰지 않을 기능)는 넣지 않아요.
- 이미지가 깨져 보이면 파일뿐 아니라 슬라이드 보기에서도 나오는지 확인해요.

## 6. HTML과 배포

교안은 [swy-lecturenote](https://github.com/loreenkim0301/swy-lecturenote) 저장소의 강의별 폴더에 올리고, GitHub Pages 배포 후 실제 페이지에서 확인해요.

- 폴더 이름은 날짜+주제(예: 261019-ai-report-plan), 저장소 첫 페이지에 교안 링크를 추가해요.
- HTML은 시맨틱 마크업으로, 정보 구조별로 태그를 묶어요(세션 section, 절 topic, figure·figcaption, 표, 목록).
- 실습 파일은 교안 폴더 data/에 두고 다운로드 카드로 연결해요.
- 배포 뒤 확인: 이미지가 모두 열리는지, 내부 링크(#절 번호)가 깨지지 않았는지, 사이드 목차와 타임테이블 문구가 본문과 맞는지
- 슬라이드 보기는 지연 로딩 이미지를 기다리다 멈출 수 있어요. 이미지를 즉시 로딩으로 바꾸고 8초 제한을 둔 수정본을 써요(10/14 교안은 미수정).
- QR코드와 축약주소를 넣을 수 있는 영역을 왼쪽 사이드바에 배치해요.

## 7. 보고 방식

로린님께는 결과·미확인 사항·다음 할 일을 링크와 함께 전달하고, 본문에는 넣지 않아요.

- 답변은 "사전지침 V1에 따라 답변합니다"로 시작하고, 칭찬 없이 비판적으로 써요.
- 처리가 필요한 항목마다 링크(페이지, 커밋, 메일, 문서)를 붙여요.
- 테스트하지 않은 것과 확인되지 않은 것을 따로 적어요.
- 고객사 메일은 초안까지만 만들고, 발송은 로린님 확인 뒤에 해요.
- 작업 내역은 프로젝트 작업 로그에 남겨요.
- 시간은 KST, 금액은 원(KRW)으로 써요.
