## 1. 문구와 톤

교안 본문은 학생에게 하는 안내 문장으로만 써요. 만든 사람에게 남기는 메모나 테스트 보고 투는 넣지 않아요.

| 구분 | 규칙 | 예시 |
| --- | --- | --- |
| 지울 것 | 테스트 결과를 보고하는 문장 | "회의록 템플릿은 보이지 않아요", "실제로 돌려 보니 ~였어요", "25분 넘게 멈췄어요" |
| 바꿔 쓸 것 | 관찰한 현상은 학생이 확인할 점으로 | "~인지 확인해요", "~할 수 있어요" |
| 남길 것 | 실행 화면의 날짜·계정 표기 | "(2026년 10월 15일 Plus 계정 실제 실행 화면)" |
| 남길 것 | 실습 사용량 기록 | "크레딧 0, 주간 무료 할당량 21% 사용 (2026-10-15 기준)" |
| 남길 것 | 공식 출처의 확인일·갱신일 | "· 2026-10-15 확인", "(2026-09-24 갱신)" — 최신성을 보여 줌 |

- 대상은 교육과정마다 다르므로 대상 확인 필요
- 사용 가능 툴과 사용 불가 툴은 교육과정마다 다르므로 확인 필요
- 버튼·메뉴 이름은 화면에 보이는 그대로 [ ]로 적어요. 예: [보기 및 내보내기], [내 문서]
- 사람 이름이 들어가는 곳은 강사 실명(김**)을 써요.
- 강사의 개인정보가 표시되는 부분은 마스킹해요.

## 2. 근거와 검증

출처를 두 번 확인하지 않은 내용은 교안에 쓰지 않아요. 도구의 기능은 공식 가이드와 실제 실행 화면 둘 다로 확인해요.

1. 기능 설명은 공식 가이드(Help Center)를 먼저 찾고, 근거는 참고 박스에 링크와 확인일로 남겨요.
2. 실습 프롬프트는 실제 계정에서 실습 파일로 돌려 본 뒤에 넣어요.
3. 공식 가이드에 없는 기능은 본문 실습에서 빼고, "공식으로 제공하는 것"을 참고 박스로 안내해요. 예: HWP·HWPX 내보내기 삭제 → Word·PDF·Markdown, XLSX 안내
4. 공식 가이드와 실제 화면이 다르면 실제 화면에서 되는 방법으로 실습을 짜고, 차이는 참고 박스에 적어요. 예: 사본 만들기 대신 "새 파일을 따로 만들어 줘"
5. 오래 멈추는 기능은 실습 경로에서 빼고 되는 경로로 바꿔요. 예: AI 시트 차트 → 홈 입력창
6. 파일 구조만 확인하고 실제 프로그램에서 열어 보지 않은 결과는 "확인되지 않음"으로 구분해요.
7. 조사가 수집되지 않았으면 있는 척 정리하지 않고, 모인 것이 없다고 그대로 알려요.

## 3. 구성

뼈대는 고객사 커리큘럼, 내용은 우리가 검증한 실습 예시와 흐름으로 채워요.

- 고객사가 준 커리큘럼 표를 찾아 교안과 대조하고, 커리큘럼 키워드가 빠진 곳이 없는지 확인해요.
- 기준 도구는 유료 버전(강사 계정)으로 하되, 학생 계정 제공 여부는 고객사에 확인해요.
- 모두 같은 설정으로 맞추는 단계(모델·모드)는 교안 맨 앞에 둬요.
- 도입은 워크플로우 스케치(내 업무 쓰기 → 단계로 쪼개기)로 시작해요.
- 같은 주제를 다른 교안에서 다뤘다면 더 최근 교안의 내용을 써요. 예: 차트 만들기는 10/14 교안 기준
- 시간이 모자라면 부차적인 파트는 삭제해요. 예: 정리 규칙서·검증용 보고서 파트 삭제
- 수강 기관에서 쓸 수 없는 도구는 표현까지 본문에서 빼요. 예: Microsoft 365·엑셀
- 기능 안내는 "찾기 → 채우기 → 만들기 → 저장 → 불러와 쓰기"처럼 실무 워크플로우 순서로 엮어요.

## 4. 실습과 프롬프트

프롬프트는 복사해서 바로 쓸 수 있게 넣고, 결과는 내 자료나 기준값과 대조하게 해요.

- 프롬프트는 복사 박스에 **요청 / 내용 / 형식** 3줄로 써요.
- 바꿔 넣을 자리는 [ ]로 비워요.
- 자료에 없는 칸은 [확인 필요]로 남기라고 프롬프트에 넣어요.
- AI가 없는 내용을 덧붙이는 지점(할 일, 연도, 숫자)은 "~는 추가하지 마"를 프롬프트에 넣고, 결과 확인 항목으로도 안내해요.
- 데이터 실습에는 기준값 표를 바로 달고, "숫자가 다르면 무엇을 물어볼지"까지 써요.
- 실습마다 결과 확인 체크리스트를 두어요.
- 실습 데이터는 가상 회사(셀렉트마켓) 예시를 쓰고, 실제 업무 자료는 가상 값으로 바꿔 올리라고 안내해요.
- 크레딧이 드는 작업은 미리 알리고, 기본은 무료 할당량으로 되는 설정(표준 모드)으로 짜요.

## 5. 화면 캡처

캡처는 실제 계정으로 실습을 돌리며 찍고, 해당 단계 바로 아래 넣어요.

- 단계마다 "어디를 누르는지"가 보이는 화면과 "결과"가 보이는 화면을 찍어요.
- AI가 틀린 부분이 드러나는 화면도 넣고, 설명에는 학생이 확인할 점을 써요.
- 캡션은 학생용 안내 문장으로 쓰되, 실행 날짜·계정 표기는 남겨요(1장 표 참고).
- 이미지는 대체 텍스트(alt)에 화면 내용을 적고, 없어도 되는 캡처(막힌 경로, 쓰지 않을 기능)는 넣지 않아요.
- 이미지가 깨져 보이면 파일뿐 아니라 슬라이드 보기에서도 나오는지 확인해요.
- 누를 곳 표시와 화질은 12장을 따라요.

## 6. HTML과 배포

교안은 [swy-lecturenote](https://github.com/loreenkim0301/swy-lecturenote) 저장소의 강의별 폴더에 올리고, GitHub Pages 배포 후 실제 페이지에서 확인해요.

- 폴더 이름은 날짜+주제(예: 261019-ai-report-plan), 저장소 첫 페이지에 교안 링크를 추가해요.
- HTML은 시맨틱 마크업으로, 정보 구조별로 태그를 묶어요(세션 section, 절 topic, figure·figcaption, 표, 목록).
- 실습 파일은 교안 폴더 data/에 두고 다운로드 카드로 연결해요.
- 배포 뒤 확인: 이미지가 모두 열리는지, 내부 링크(#절 번호)가 깨지지 않았는지, 사이드 목차와 타임테이블 문구가 본문과 맞는지
- 슬라이드 보기는 지연 로딩 이미지를 기다리다 멈출 수 있어요. 이미지를 즉시 로딩으로 바꾸고 8초 제한을 둔 수정본을 써요(10/14 교안은 미수정).
- QR코드와 축약주소를 넣을 수 있는 영역을 왼쪽 사이드바에 배치해요.

## 7. 보고 방식

로린님께는 결과·미확인 사항·다음 할 일을 링크와 함께 전달하고, 본문에는 넣지 않아요.

- 답변은 "사전지침 V1에 따라 답변합니다"로 시작하고, 칭찬 없이 비판적으로 써요.
- 처리가 필요한 항목마다 링크(페이지, 커밋, 메일, 문서)를 붙여요.
- 테스트하지 않은 것과 확인되지 않은 것을 따로 적어요.
- 고객사 메일은 초안까지만 만들고, 발송은 로린님 확인 뒤에 해요.
- 작업 내역은 프로젝트 작업 로그에 남겨요.
- 시간은 KST, 금액은 원(KRW)으로 써요.


## 8. 세션 설계: 형식을 채우려고 단계를 넣지 않아요

2026-11-04, AI PM 2주차 수요일 교안에 로린님이 남긴 스위노트 댓글 9개에서 나온 규칙이에요. 댓글 하나하나는 "삭제", "의미 없음"이었지만, 이유는 모두 같았어요. **단계가 학생의 실제 결과물을 바꾸지 않는데, 정해 둔 틀(기록표·점검·실험)을 채우려고 들어가 있었어요.** 앞서 받은 피드백도 같은 이유였어요. 7단계 틀에 끼워 넣은 '실패 케이스', 품질이 낮은 참고 점검표, 표와 똑같은 텍스트 템플릿이 그 예예요.

### 무엇을 왜 고쳤나

| 댓글 | 고치기 전 | 왜 문제였나 | 규칙 |
| --- | --- | --- | --- |
| 불필요함 삭제 | 아무 질문을 프로젝트 안/밖에 보내고 차이 2개 적기 | 기능을 써 본 척만 하고, 학생 결과물(PRD)과 이어지지 않음 | 기능의 효과는 그날의 실제 산출물로 확인해요 |
| 프롬프트 교체 | "나 / 자료 / 규칙"을 빈칸에 넣어 지침을 처음부터 쓰기 | 지침은 해 본 일을 반복하려고 쓰는 것인데, 해 본 일 없이 상상으로 씀 | 지침·템플릿·규칙은 이미 한 작업의 대화에서 뽑아요 |
| 항목 삭제 | 지침에 확인할 수 없는 줄이 있는지 점검받기 | 점검을 위한 점검. 결과물이 달라지지 않음 | 점검 단계는 결과물을 고치는 경우에만 넣어요 |
| 기록표도 의미 없음 | 지침 예시 표 + 빈 표 | 다음 단계에서 쓰지 않는 표. 채우는 것 자체가 목적이 됨 | 기록표는 다음 단계나 결과물에 들어갈 때만 둬요 |
| 삭제 | 실험: 지침과 반대로 요청해 보기 | 수업 목표와 관계없는 곁가지 | 실험은 수업 목표를 직접 보여 줄 때만 둬요 |
| 결과 변경 | 결과물 "안/밖 차이 2줄" | 결과물이 기능의 쓸모를 보여 주지 못함 | 결과물은 "이 기능을 쓰면 내 산출물이 이렇게 달라진다"로 정해요 |
| 이 문구 진짜 의미 없어 | "메모리는 편해요." | 정보가 없는 문장 | 정보가 없는 문장은 쓰지 않아요 |
| 왜 섞여 있어? | 메모리와 예약 작업을 한 문단에 섞음 | 두 기능이 오가서 무엇을 설명하는지 알 수 없음 | 한 문단·한 상자에는 한 기능만 써요 |
| 분리해야지 | "들어가는 길 · 메모리와 예약 작업" 한 상자 | 위와 같음 | 들어가는 길도 기능마다 따로, 그 기능 설명 바로 뒤에 둬요 |

### 세션을 짤 때의 순서

도구·기능을 가르치는 세션은 아래 한 줄기로만 써요.

1. **○○란?** 한두 문장으로 정의해요.
2. **어떤 문제를 해결하나요?** 이 기능이 없으면 무엇이 불편한지 쓰고, 공식 도움말의 예를 들어요.
3. **조심할 점**: 공식 문서에 있는 한계와 주의 사항을 써요.
4. **써 볼까요?** 그날 실제 산출물(PRD, 이벤트 페이지 등)에 바로 써요.
5. **결과**: 기능을 쓰기 전과 쓴 뒤의 산출물을 비교해요.

### 단계를 넣기 전에 묻는 질문

- 이 단계를 지우면 학생의 결과물이 달라지나요? 달라지지 않으면 지워요.
- 이 표·점검·실험은 틀(7단계, A·B·C 종류)을 채우려고 넣었나요, 수업 목표에 필요해서 넣었나요?
- 이 산출물은 앞 시간에 만든 것을 이어서 쓰나요, 처음부터 새로 만들게 하나요? 이어서 쓰는 쪽을 골라요.
- 이 문장을 지우면 학생이 모르는 것이 생기나요? 생기지 않으면 지워요.

## 9. 문장

- 한 문장에는 한 생각만 써요. 길면 나눠요.
- 주어와 목적어를 빼지 않아요. "점검받아요" → "클로드에게 명세서를 점검받아요"
- 번역투를 쓰지 않아요. "판정의 첫 기준은" → "가장 먼저 물을 것은"
- 같은 설명을 두 곳에 쓰지 않아요. 예: 교육 개요의 세션 진행 방식과 수업 전 준비의 안내가 같은 내용이었음 → 하나만 남김
- 교육 개요와 수업 전 준비는 항목마다 한 문장으로 써요. 자세한 조건은 해당 세션 안에 둬요.
- 빈 표 아래에 같은 내용의 텍스트 템플릿을 또 두지 않아요.

## 10. 앞에서 만든 결과물을 부를 때

2026-11-05, AI PM 2주차 교안에서 로린님이 지적한 규칙이에요. "월요일 이벤트 페이지 v2", "간단 PRD v1"처럼 **버전 이름으로만 부르면** 학생은 그게 무엇이었는지 기억하지 못해요. 수업 순서가 바뀌면 번호도 맞지 않게 돼요.

| 고치기 전 | 고친 뒤 |
| --- | --- |
| 월요일 이벤트 페이지 v2 대화를 열고 | 월요일에 이벤트 페이지를 만들었던 것 기억하시나요? 그 대화를 열고 |
| 어제 간단 PRD v1을 만든 대화를 열고 | 오전 3세션에서 간단 PRD를 만들었던 대화 기억하시나요? 그 대화를 열고 |
| [간단 PRD v1 붙여 넣기] | [3세션에서 만든 간단 PRD 붙여 넣기] |
| 이벤트 페이지 v4를 index.html로 | 2세션에서 IA로 모든 화면을 넣어 만든 이벤트 페이지를 index.html로 |

- 이전 결과물은 **언제(요일·세션) + 무엇으로 만든 것인지**를 풀어서 불러요. 앞 시간 일이면 "기억하시나요?"로 떠올리게 해요.
- 프롬프트의 [ ] 칸도 같은 방식으로 써요.
- 지금 만드는 결과물에 이름을 붙일 때(결과물 칸, 파일 이름)는 버전을 써도 돼요.
- '어제'·'오늘'은 요일이 바뀌면 틀려져요. 다른 날로 옮겨질 수 있는 세션에서는 요일이나 세션 번호로 써요.

## 11. 세부 목차: 고정 단계가 아니라 수업 흐름으로

2026-11-05, AI PM 2주차 월요일 교안을 재구성하며 정한 규칙이에요. 모든 세션을 같은 7단계(개념 → 예시 → 실습 템플릿 → 프롬프트로 시작하기 → 점검·피드백 → 실패 케이스 → 결과)로 짜니, 왼쪽 목차와 실제 수업 순서가 맞지 않았어요. 수업에서 한 실습은 끝에 '추가 실습'으로 붙어 있었어요. 세부 목차는 학생의 눈높이에 맞춰 정보를 조금씩 주고, 실습 중심으로 짜요.

| 원칙 | 이렇게 해요 | 예 |
| --- | --- | --- |
| 목차 제목 | '1-1. 개념' 같은 단계명 대신 학생이 하는 일로 써요 | 1-3. 셀렉트마켓 문제를 한 문장으로 써 보기 |
| 순서 | 셀렉트마켓으로 먼저 해 보고 → 내 주제로 바꾸고 → 점검받는 흐름으로 놓아요 | 1-3 셀렉트마켓으로 써 보기 → 1-4 내 회사 문제 3개 → 1-5 점검받기 |
| 실습 절 | '실습 템플릿'과 '프롬프트로 시작하기'를 따로 두지 않고 한 절로 합쳐요. 빈칸을 먼저 손으로 채우고, 막히면 프롬프트를 써요 | 2-3. AI와 질문 하나씩 주고받으며 내 5 Whys 하기 |
| 실패 케이스 | 독립 절로 두지 않고, 점검 절 안의 '이렇게 하면 결과가 틀어져요'로 넣어요(8장) | 4-4 점검 절 안의 '근거 없이 요청하기' |
| 추가 실습 | 수업에서 실제로 진행한 실습은 끝에 붙이지 않고, 진행한 자리에 넣어요 | 솔루션 떠올리기 → 3-2(가설 쓰기 앞) |
| 블록 표시 | 절 안의 블록 앞에 종류를 표시해요: 설명 · 예시 · 빈 템플릿 · 프롬프트 · 실행 결과 · 확인할 점 · 막히면. 빈 템플릿 표는 노란 머리·점선 테두리로 예시 표와 구분해요 | [빈 템플릿] 표, [프롬프트] 복사 상자 |
| 단계가 긴 실습 | 한 절 안에서 STEP 1, 2, 3…으로 나누고, STEP마다 설명 → 예시 → 내 것 쓰기 순서로 써요 | 화요일 1-3 STEP 1~6(시트 준비 → 1차 → 2차 → 3차) |
| 관련 문구 | 목차 구성을 바꾸면 주간 홈·교육 개요의 진행 방식 설명도 같이 고쳐요 | '모든 세션을 같은 7단계로' 문구 삭제 |

- 재구성할 때 본문 내용은 빼지 않아요. 순서, 묶음, 제목만 바꿔요. 빼야 할 내용은 8장 기준으로 따로 판단해요.
- 절 번호를 바꾸면 본문 속 번호 참조(예: '1-8에서 찾은 주제')도 함께 고쳐요.

## 12. 캡처에는 누를 곳을 표시하고, 화질이 깨지지 않게

2026-11-05, AI PM 2주차 목·금(볼트·구글 AI 스튜디오) 교안을 고치며 정한 규칙이에요. 화면 전체 캡처만 넣으니 학생이 "여기서 어디를 눌러야 해요?"를 다시 물었어요. 캡처는 보여 주는 그림이 아니라 따라 누르는 지도예요.

| 원칙 | 이렇게 해요 | 예 |
| --- | --- | --- |
| 누를 곳 | 빨간 실선 상자로 감싸고, 누르는 순서대로 빨간 동그라미 번호(1, 2, 3…)를 붙여요 | 볼트 첫 화면: 1 Get Started → 2 가운데 입력창 |
| 확인할 곳 | 누르지 않고 눈으로 볼 곳은 주황 점선 상자로 감싸요. 번호는 붙이지 않아요 | 'Public' 표시, '무료 등급', 저장된 이름 한 줄 |
| 번호 위치 | 번호가 버튼 글자를 가리지 않게 상자 바깥(왼쪽 → 아래 → 위)에 둬요 | 작은 탭·아이콘 버튼은 번호를 아래에 |
| 본문과 맞추기 | 단계 문장에 같은 번호를 적어요. 캡션 끝에 '빨간 번호 = 누를 곳 · 주황 점선 = 확인할 곳'을 적어요 | 가운데 입력창(①)에 넣고 화살표(②)로 보내요 |
| 해상도 | 레티나(2배)로 찍어요. 원본이 1배면 표시를 2배 캔버스에 그려 선과 글자가 번지지 않게 해요 | 원본 650px → 1300px 파일, 화면에는 650px로 |
| 표시 크기 | 원본 너비보다 크게 늘려 보이지 않아요. img에 원본 너비(style="width:…px")를 주고 max-width:100%로 줄이기만 해요 | 418px 캡처를 760px로 늘리지 않기 |
| 원본 보존 | 표시는 원본에 덮어쓰지 않고 '<이름>-hl.png'로 따로 저장해요. 다시 찍으면 표시도 다시 그려요 | bolt-publish.png → bolt-publish-hl.png |
| 개인 정보 | 표시를 그리면서 이름·이메일·프로젝트 목록 등 개인 정보가 보이면 가려요(1장) | Firebase 첫 화면 인사말 이름, 지원 이메일 |

- 결과만 보여 주는 화면(완성된 페이지, AI 답변)은 확인할 곳만 점선으로 표시해요. 누를 곳이 없으면 번호를 붙이지 않아요.
- 한 캡처에 번호는 3개까지만 둬요. 더 많으면 캡처를 나눠요.
- 배포 전 확인: 표시 그림이 모두 열리는지, 번호가 글자를 가리지 않는지, 본문 번호와 그림 번호가 같은지 눈으로 봐요.
