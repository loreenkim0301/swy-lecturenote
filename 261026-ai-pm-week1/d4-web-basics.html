SESSION 1 · 09:00–10:00

웹의 등장인물: 브라우저·서버·데이터베이스

우리가 매일 쓰는 쇼핑몰도 사실은 세 등장인물이 주고받는 대화로 움직여요. PM은 이 대화의 흐름을 알아야 개발자, 디자이너, 그리고 AI에게 정확하게 일을 맡길 수 있어요.

1-1. 세 등장인물

내 쪽

브라우저 (클라이언트)

Chrome처럼 웹페이지를 보여 주는 프로그램이에요. 내 컴퓨터나 휴대폰과 그 안의 브라우저를 묶어 클라이언트(서비스를 요청하는 쪽)라고 불러요.

저쪽

서버

웹페이지, 사이트, 앱의 파일을 보관하고 있는 컴퓨터예요. 브라우저가 요청하면 페이지 코드의 사본을 보내 줘요.

창고

데이터베이스

회원, 상품, 주문 기록처럼 계속 쌓이는 정보를 정리해 보관하는 곳이에요. 서버가 필요할 때 꺼내 보고, 새로 적어 넣어요.

클라이언트와 서버의 정의는 MDN Web Docs(웹 기술 공식 학습 문서)의 설명을 바탕으로 했어요. 데이터베이스는 이 교과 뒷부분(SQLite, Supabase)에서 직접 다뤄요. 오늘은 "서버 뒤에 정보 창고가 있다"는 것만 기억해요.

1-2. 주소(URL)와 도메인

URL은 웹페이지, 이미지, 영상 같은 자료가 인터넷의 어디에 있는지 알려 주는 글자 줄이에요. 아래는 가상의 셀렉트마켓 주문 조회 주소예요. (실제로는 열리지 않는 연습용 주소예요.)

예시 주소 · 가상의 셀렉트마켓
https://www.selectmarket.example/orders?id=SM-1029
부분예시쉽게 말하면
통신 방식https://브라우저와 서버가 어떤 약속으로 대화할지. s는 보안 연결이라는 뜻이에요.
도메인(Domain)www.selectmarket.example가게 간판 이름. 사람이 기억하기 쉬운 이름이에요.
경로(Path)/orders가게 안의 어느 코너인지. 여기서는 "주문" 코너예요.
추가 정보?id=SM-1029코너에 가서 전하는 메모. "주문번호 SM-1029를 보여 주세요."
도메인 이름은 어떻게 진짜 서버를 찾아갈까
컴퓨터끼리는 192.0.2.172 같은 숫자 주소(IP 주소)로 서로를 찾아요. 사람이 입력한 도메인 이름을 이 숫자 주소로 바꿔 주는 시스템이 DNS예요. MDN은 DNS를 "웹사이트의 주소록"에 비유해요.

1-3. 주소창에 주소를 입력하면 일어나는 일

1주소 찾기브라우저가 DNS에서 서버의 진짜 주소를 찾아요
2요청 보내기"이 페이지 사본을 보내 주세요"라고 서버에 요청해요
3승인서버가 "200 OK"로 답하고 파일을 보내기 시작해요
4조각 전송파일은 작은 조각(패킷)으로 나뉘어 와요
5화면 완성브라우저가 조각을 모아 페이지를 보여 줘요

실습 채팅에 짧게 답해요. "내가 오늘 아침 처음 연 웹사이트의 도메인은 무엇이었나요?" 예: www.naver.com

SESSION 2 · 10:00–11:00

요청과 응답, 그리고 API

브라우저와 서버의 대화는 늘 요청(Request)과 응답(Response) 한 쌍으로 이루어져요. 이 대화를 식당 주문에 빗대어 보면 프론트엔드, 백엔드, API가 한 번에 정리돼요.

2-1. 식당 주문으로 보는 웹

식당웹 서비스설명
손님사용자원하는 것을 고르고 주문하는 사람
홀(메뉴판, 테이블)프론트엔드 (Front-end)사용자 눈에 보이고 손으로 누르는 화면. 브라우저에서 돌아가요.
주문서 양식과 점원API"이런 형식으로 주문하면, 이런 형식으로 내어 드려요"라는 정해진 주문 창구. 프로그램끼리 대화하는 약속이에요.
주방백엔드 (Back-end), 서버손님에게 보이지 않는 곳에서 주문을 처리하는 곳. 규칙 확인, 계산, 기록을 맡아요.
식재료 창고데이터베이스주방이 필요할 때 꺼내 쓰는 재료(회원·상품·주문 정보)
주문 → 음식이 나옴요청 → 응답손님이 주문서를 내면(요청), 주방이 음식을 내보내요(응답).
API가 왜 중요할까요
손님이 주방에 직접 들어가지 않아도 주문서만 정확하면 음식이 나와요. API도 같아요. 화면을 만드는 사람과 주방(서버)을 만드는 사람이 달라도, API라는 약속만 지키면 서로 연결돼요. 이 교과 뒷부분에서 배우는 "AI API 호출"도 결국 AI 회사의 주방에 정해진 주문서를 보내는 일이에요.

2-2. 셀렉트마켓의 "주문 조회" 한 번

고객이 셀렉트마켓에서 [주문 조회] 버튼을 한 번 누르면, 뒤에서는 이런 일이 일어나요.

1클릭고객이 화면(프론트엔드)에서 [주문 조회]를 눌러요
2요청브라우저가 서버의 주문 API로 "SM-1029 주문 정보 주세요"를 보내요
3확인서버(백엔드)가 로그인한 본인의 주문인지 확인해요
4꺼내기서버가 데이터베이스에서 주문 기록을 찾아요
5응답서버가 결과를 돌려주고, 브라우저가 "배송 중"을 화면에 보여 줘요

서버의 응답에는 상태 코드라는 숫자가 함께 와요. 대표적인 두 가지만 알아 두세요.

상태 코드뜻식당으로 말하면
200성공"주문하신 음식 나왔습니다."
404찾을 수 없음"그런 메뉴는 없습니다."

4-1. 세 가지 언어의 역할

뼈대

HTML

페이지에 무엇이 있는지 정해요. 제목, 문단, 버튼 같은 내용을 태그로 감싸 구조를 만들어요.

옷

CSS

어떻게 보일지 정해요. 색, 글꼴, 여백처럼 꾸미는 일을 맡아요.

움직임

JavaScript

누르거나 입력했을 때 어떻게 반응할지 정해요. 버튼을 누르면 안내 창이 뜨는 것 같은 동작이에요.

HTML 태그는 보통 여는 태그, 내용, 닫는 태그 세 부분으로 되어 있어요. 닫는 태그에는 이름 앞에 빗금(/)이 붙어요.

태그 한 개의 생김새
<p>매일 쓰는 생활용품을 골라 담는 작은 온라인 가게예요.</p>

여기서 <p>는 여는 태그(p는 문단 paragraph), 가운데는 내용, </p>는 닫는 태그예요.

4-2. 셀렉트마켓 소개 페이지 예시 코드

AI가 만들어 준 코드라고 생각하고 천천히 읽어 봐요. 이해가 안 되는 줄이 있어도 괜찮아요. 세션 7에서 AI에게 설명을 시켜요.

예시 코드 · 셀렉트마켓 소개 HTML
<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="UTF-8">
  <title>셀렉트마켓 소개</title>
  <style>
    body { font-family: sans-serif; margin: 40px; }
    h1 { color: #2f6f4e; }
    .btn { background: #2f6f4e; color: white; padding: 10px 20px; border: none; }
  </style>
</head>
<body>
  <h1>셀렉트마켓에 오신 것을 환영해요</h1>
  <p>매일 쓰는 생활용품을 골라 담는 작은 온라인 가게예요.</p>
  <button class="btn" onclick="alert('주문 조회 화면은 준비 중이에요')">주문 조회하기</button>
</body>
</html>
구역무엇이 들어 있나
<head> ~ </head>화면 본문에는 보이지 않는 페이지 정보(글자 방식, 탭 제목)와 꾸미기 규칙(CSS, <style> 안)
<body> ~ </body>화면에 보이는 내용(HTML). 버튼의 onclick 부분은 누르면 일어날 동작(JavaScript)

SESSION 7 · 16:30–17:40

AI에게 코드 설명 시키고, 설명을 검증하기

AI는 코드를 친절하게 설명해 주지만, 가끔 코드에 없는 내용을 그럴듯하게 덧붙이기도 해요. 그래서 설명을 받는 것으로 끝내지 않고, 실제 코드와 대조하는 것까지가 오늘의 실습이에요.

7-1. 코드 설명 요청하기

실습 ChatGPT와 Claude 중 하나를 먼저 열고, 아래 프롬프트를 복사해 붙여 넣어요. [ ] 자리에는 4-2 예시 코드 전체를 붙여 넣어요.

프롬프트 · 복사해서 사용하세요
요청: 아래 HTML 코드가 줄마다 무엇을 하는지 프로그래밍을 처음 배우는 비개발자 눈높이로 설명해 줘.
내용: [4-2 셀렉트마켓 소개 HTML 예시 코드 전체를 여기에 붙여 넣기]
형식: 표 하나로 정리해 줘(줄 번호 / 그 줄의 코드 / 하는 일 / 화면에서 보이는 곳). 전문 용어는 처음 나올 때 괄호 안에 한 줄로 풀어 줘. 코드를 고치거나 새 기능을 추가하지 말고, 코드에 없는 내용은 설명에 덧붙이지 마. 확실하지 않은 줄은 [확인 필요]로 남겨 줘.

7-2. AI 설명과 실제 코드 대조하기

AI의 표를 4-2 코드 옆에 나란히 놓고 하나씩 확인해요.

  • AI 표의 줄 수가 실제 코드의 줄 수(17줄)와 맞나요? 빠지거나 합쳐진 줄이 있으면 표시해요.
  • AI가 <title>은 브라우저 탭 이름, <h1>은 화면의 큰 제목이라고 구분해 설명했나요?
  • #2f6f4e가 제목 색(h1)과 버튼 배경색(.btn) 두 곳에 쓰였다고 맞게 설명했나요?
  • onclick 부분을 "버튼을 누르면 안내 창이 뜨는 동작"으로 설명했나요?
  • 코드에 없는 기능(예: 실제로 주문을 조회한다, 데이터베이스에 연결된다)을 있는 것처럼 말하지 않았나요?
  • [확인 필요]로 남긴 줄이 있다면, 어느 줄인지 적고 강사에게 질문했나요?
  • AI가 "이 줄을 바꾸면 제목 색이 바뀐다"고 한 줄을 실제로 고쳐 저장하고 새로고침했을 때, 정말 그 부분만 바뀌었나요?
"버튼을 누르면 주문이 조회된다"는 설명이 나왔다면
예시 코드의 버튼은 안내 창만 띄워요. 세션 2에서 본 것처럼 진짜 주문 조회에는 서버, API, 데이터베이스가 필요한데, 이 코드에는 그런 부분이 없어요. 이렇게 AI의 설명을 오늘 배운 구조로 검증하는 것이 PM의 일이에요.

7-3. 한 번 더 묻기: 고칠 위치 찾게 하기

선택 시간이 남으면 같은 대화창에서 이어서 물어봐요. AI가 알려 준 줄이 4-3 퀴즈 정답과 같은지 비교해요.

프롬프트 · 복사해서 사용하세요
요청: 위 코드에서 큰 제목의 색만 남색으로 바꾸려면 어느 줄을 어떻게 고쳐야 하는지 알려 줘.
내용: 버튼 색은 지금 그대로 둬야 해. 위에 붙여 넣은 셀렉트마켓 소개 HTML 코드 기준이야.
형식: 고칠 줄의 지금 코드 1줄, 고친 뒤 코드 1줄, 이유 1문장. 다른 줄은 바꾸지 말고, 코드 전체를 다시 쓰지 마.
  • AI가 h1 { color: ... } 줄 하나만 고치라고 했나요?
  • 버튼 줄(.btn)은 건드리지 않았나요?
WRAP-UP

오늘 정리와 과제

  • 웹은 브라우저(클라이언트) → 서버 → 데이터베이스가 요청과 응답을 주고받으며 움직여요. API는 그 사이의 정해진 주문 창구예요.
  • 개발자 도구로 바꾼 것은 내 브라우저의 사본이라 저장되지 않아요. 진짜로 바꾸려면 원본 파일을 고쳐야 해요.
  • HTML은 뼈대, CSS는 옷, JavaScript는 움직임이에요. AI가 만든 코드에서 고칠 줄 하나를 찾는 힘이 앞으로 가장 많이 쓰여요.
  • AI의 설명은 받는 것으로 끝내지 않고, 실제 코드와 대조하고 직접 바꿔 확인해요.
