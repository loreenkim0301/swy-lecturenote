비개발자를 위한 클로드코드 입문

클로드(Claude) 웹 채팅 + Claude Code + GitHub로, 코드를 몰라도 나만의 웹페이지 하나를 인터넷에 진짜로 배포해보는 실습 교안입니다.

이 교안에서 배우는 것

  • Claude 웹 채팅에게 문장 하나로 요청해서, 웹페이지 파일을 만들고 GitHub에 자동으로 올리는 것을 경험합니다.
  • GitHub에서 그 웹페이지를 실제 인터넷 주소로 열어볼 수 있게(배포) 설정하는 방법을 배웁니다.
  • 중간에 막히는 대표적인 상황(Pages 꺼짐, 저장소가 비공개)을 스스로 해결하는 방법을 익힙니다.

준비물

  • GitHub 계정 1개 (없다면 github.com/join에서 무료로 가입)
  • 웹페이지를 담을 GitHub 저장소(repository) 1개 — 이번 실습 예시: github.com/loreenkim0301/swy-lecturenote
  • Claude 웹 채팅(Claude Code) 접속 화면 — claude.ai/code

STEP 1. Claude에게 딱 한 문장으로 요청하기

Claude Code 채팅창에 아래 문장을 그대로 입력합니다. 코드를 몰라도 됩니다 — 이 문장 하나가 시작입니다.

여기서 시작한다. hello 페이지를 하나 띄워서 배포해줘.
Claude Code — Hello 페이지 배포
여기서 시작한다.

세션 초기화됨

  • 클라우드 컨테이너 설정
  • 리포지토리 1개 복제 완료
  • Claude Code 시작됨
  • 전송 중...

▲ Claude Code 채팅 화면(재현 이미지) — 요청을 보내면 왼쪽에 진행 상황 체크리스트가 자동으로 올라옵니다.

💡 이 한 문장을 보내는 순간, Claude가 스스로 index.html(웹페이지 파일)과 배포용 설정 파일을 만들고, 그것을 GitHub 저장소에 커밋(commit)·푸시(push)까지 전부 대신 해줍니다. 여러분은 클릭 몇 번만 하면 됩니다.

STEP 2. Claude가 자동으로 한 일 확인하기

Claude가 작업을 마치면 보통 다음과 같은 결과를 보고합니다.

  • 👋 인사말이 담긴 index.html 웹페이지 파일 생성
  • push할 때마다 자동으로 배포해주는 GitHub Actions 설정 파일 생성
  • GitHub 저장소에 커밋 & 푸시 완료
⚠️ 첫 시도에서는 배포가 실패할 수 있습니다! 정상입니다. 이유는 GitHub 저장소에서 "Pages(페이지 공개 기능)"가 아직 켜져 있지 않기 때문입니다. 아래 STEP 3에서 딱 한 번만 켜주면 됩니다.

STEP 3. GitHub에서 Pages(페이지 공개 기능) 켜기

웹사이트를 인터넷에서 보이게 하려면, GitHub 저장소에서 버튼 하나만 누르면 됩니다.

1저장소 페이지로 들어가기

  1. 브라우저를 열고 내 GitHub 저장소 주소로 들어갑니다.
    예) https://github.com/내계정/저장소이름
  2. 로그인이 안 되어 있으면 먼저 로그인합니다.

이번 실습 저장소로 바로 가기: github.com/loreenkim0301/swy-lecturenote

2"Settings"(설정) 메뉴 찾기

  1. 저장소 화면 맨 위쪽 탭들(Code / Issues / Pull requests / Actions / Projects / Settings) 중에서
  2. 맨 오른쪽 끝의 ⚙️ Settings 탭을 클릭합니다. (화면이 좁으면 ... 더보기 안에 숨어있을 수 있어요)

3"Pages" 메뉴 찾기

  1. Settings 화면 왼쪽에 세로로 긴 메뉴 목록이 보입니다.
  2. 아래로 내리다 보면 "Pages"라는 글자가 있습니다. ("Code and automation" 그룹 아래)
  3. Pages를 클릭합니다.
💡 팁: 메뉴를 못 찾겠으면 키보드에서 Ctrl + F (맥은 Command(⌘) + F)를 눌러 작은 검색창을 띄운 뒤 "Pages"라고 입력해보세요. 그 단어가 있는 곳을 바로 찾아줍니다.

4Source(소스)를 "GitHub Actions"로 바꾸기 ⭐ 제일 중요!

  1. Pages 화면의 "Build and deployment" 아래 "Source" 드롭다운을 클릭합니다.
  2. 지금은 보통 "None" 또는 "Deploy from a branch"로 되어 있습니다.
  3. 드롭다운에서 "GitHub Actions"를 선택합니다. 보통 자동으로 저장됩니다.

Pages 설정 화면 바로 가기: github.com/loreenkim0301/swy-lecturenote/settings/pages

STEP 3-1. 저장소를 실수로 Private(비공개)로 만들었다면

Pages 설정 화면에 "이 저장소는 비공개라서 유료 플랜이 필요하다"는 안내나 "Upgrade your plan" / "Make repository public" 문구가 뜬다면, 무료 계정은 비공개 저장소에서 Pages를 쓰려면 유료 플랜이 필요하기 때문입니다.

결제 없이 해결하려면 저장소를 공개(Public)로 바꾸면 됩니다.

  1. Settings 화면을 맨 아래까지 내려서 "Danger Zone"(위험 구역)을 찾습니다.
  2. "Change repository visibility" 항목 오른쪽의 "Change visibility" 버튼을 클릭합니다.
  3. 펼쳐지는 메뉴에서 "Change to public"을 선택하고, 안내에 따라 저장소 이름을 입력해 확인합니다.

Danger Zone 바로 가기: github.com/loreenkim0301/swy-lecturenote/settings (맨 아래로 스크롤)

Danger Zone
Change repository visibility This repository is currently private.

▲ GitHub 저장소 Settings 맨 아래 Danger Zone 화면(재현 이미지)

💡 공개로 바꾼 뒤에는 다시 Pages 메뉴로 가서 STEP 3의 4번(Source를 "GitHub Actions"로 선택)을 진행하면 됩니다.

STEP 4. 완성된 페이지 확인하기

Pages 설정을 마치면, Claude에게 "설정 끝났어"라고 알려주세요. Claude가 배포를 다시 실행하고 성공 여부를 확인해줍니다.

배포가 성공하면 아래와 같은 주소로 내 웹페이지를 열어볼 수 있습니다.

Q&A

Q. 배포가 계속 실패해요.
A. Settings → Pages에서 Source가 "GitHub Actions"로 되어 있는지, 저장소가 Public인지 다시 확인해보세요.

Q. 메뉴를 못 찾겠어요.
A. Ctrl + F(맥은 Command + F)로 원하는 단어를 검색하면 빨리 찾을 수 있어요.

Q. 주소로 들어갔는데 페이지가 안 보여요.
A. 처음 배포된 직후에는 1~2분 정도 걸릴 수 있습니다. 잠시 후 새로고침 해보세요.

어떻게 해야할지, 남은 한 단계 (사용자가 직접 해야 함)를 초등학생도 따라가도록 상세하게 설명.

3Ctrl+F 팁 추가 요청

키워드나 메뉴를 못 찾는다면 '컨트롤 + F키' 눌러서 해당 'Pages' 단어를 검색하면 빠르다. 라고 추가. 3단계에 추가.

4Private 저장소 관련 내용 추가 + 설정 완료 알림

그리고 나는 처음에 실수로 private 으로 만들었더니, 업그레이드 플랜하거나 퍼블릭으로 바꾸라고 되어 있었음. 이 부분 단계 중간에 추가. 설정 끝났어.
