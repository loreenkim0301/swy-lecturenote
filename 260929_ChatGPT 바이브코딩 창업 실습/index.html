1. 바이브코딩이란?

창업자의 관점에서 바이브코딩이 무엇인지 이해하고, 오늘 사용할 ChatGPT·GitHub·Vercel이 각각 어떤 역할을 하는지 살펴봅니다.

INTRO

1.1 창업자에게 바이브코딩이 필요한 이유

창업자가 모든 코드를 직접 작성할 필요는 없습니다. 다만 아이디어를 AI에게 설명하고 빠르게 화면으로 확인할 수 있다면 개발 전에 사업 아이디어를 구체화하고 다른 사람에게 보여주며 빠르게 검증할 수 있습니다.

01

아이디어 확인

머릿속 사업 아이디어를 실제 화면으로 만들어봅니다.

02

빠른 수정

문구·색상·구성을 AI와 대화하며 변경합니다.

03

직접 공유

완성된 결과를 URL로 만들어 고객·동료에게 보여줍니다.

빠른 생성은 완성의 의미가 아니라 검증의 시작입니다.
AI가 만든 내용과 기능이 실제 사업에 적합한지는 사람이 직접 확인해야 합니다.
현장에서 바이브코딩을 쓰는 이유
1. 대표가 상상한 화면을 기획자·개발자에게 더 빠르게 전달할 수 있습니다.
2. 회사 홈페이지나 앱의 프로토타입까지는 어느 정도 직접 구현해볼 수 있습니다.
3. 기획·디자인·개발의 흐름을 직접 경험하면서 각 직무에 대한 이해도를 높일 수 있습니다.

FOUNDATION

1.3 프로덕트·프로토타입·MVP

작게 만들고, 빨리 배우기. 아래는 일반적으로 창업자나 기획자가 서비스를 처음 만들어야 할 때 알아야 할 필수 기초 용어들입니다.

1. 용어 정의

PRODUCT

프로덕트

고객의 문제를 해결하는 제품·서비스와 경험 전체입니다. 화면에서 시작해 주문, 배송, 배송 완료까지 고객이 실제로 겪는 사용자 흐름도 포함합니다.

PROTOTYPE

프로토타입

아이디어와 사용자 흐름을 빠르게 확인하는 초기 모형입니다. 실제 결제나 배송이 작동하지 않아도 되며, 고객이 서비스를 이해하고 사용할 수 있는지 확인하는 데 씁니다.

MVP

최소 기능 제품

고객이 핵심 가치를 실제로 얻는지 확인하는 가장 작은 서비스입니다. 기능을 적게 넣는 것이 목적이 아니라, 가장 중요한 가정을 실제로 검증하는 것이 목적입니다.

세 용어의 관계
프로덕트는 고객에게 계속 가치를 주는 전체 서비스입니다. 프로토타입은 그 서비스의 아이디어와 흐름을 보여주는 모형이고, MVP는 고객이 실제로 써 보며 가치를 확인할 수 있는 가장 작은 운영 형태입니다.

2. 동네 반찬 정기배송 서비스 바이브코딩 사례

가상의 창업자가 “퇴근 후 저녁 준비가 부담스러운 직장인에게 주 1회 반찬을 배송한다”는 아이디어를 갖고 있다고 가정해보겠습니다. 이 서비스의 프로덕트는 홈페이지 하나가 아니라 메뉴 선택, 신청, 배송, 재주문까지의 경험 전체입니다.

바이브코딩을 모를 때

머릿속 아이디어를 글로만 정리한 뒤, 개발자나 제작 업체에 “반찬 주문 앱을 만들고 싶다”고 의뢰하기 쉽습니다. 어떤 화면이 필요한지, 고객이 어떤 순서로 신청하는지 직접 확인하기 어렵고, 수정 요청이 늘어날수록 시간과 비용도 커집니다.

처음부터 앱·결제·배송관리 기능을 모두 만들려 하면, 고객이 실제로 주문할지 확인하기 전에 큰 비용이 들어갈 수 있습니다.

바이브코딩을 알 때

비개발자도 AI에게 서비스 설명을 입력해 메뉴, 가격, 신청 버튼이 있는 한 장의 화면을 먼저 만들 수 있습니다. 이 화면을 고객에게 보여주며 메뉴와 가격, 신청 흐름을 이해하는지 확인한 뒤 필요한 기능만 다음 단계에서 개발합니다.

바이브코딩은 개발자를 완전히 대신하는 일이 아니라, 창업자가 더 구체적인 화면과 요구사항으로 검증·협업하는 방법입니다.

3. 참고: 비개발자 창업자도 할 수 있는 내 아이디어 검증 과정

처음부터 주문 앱을 만들 필요는 없습니다. 아래 수준이면 초기 검증을 시작할 수 있습니다.

1. 한 사람 정하기“퇴근이 늦은 1인 가구 직장인”처럼 처음 고객을 한 유형으로 좁힙니다.
2. 한 가지 행동 정하기고객이 주간 메뉴를 보고 ‘신청하기’를 누르는 흐름 하나만 정합니다.
3. AI로 화면 만들기ChatGPT에 메뉴, 가격, 배송 요일, 신청 버튼이 있는 한 장의 웹페이지를 요청합니다.
4. 실제 고객에게 보여주기대상 고객 3명에게 화면을 보여주고, 어떤 메뉴를 고르는지와 신청이 망설여지는 이유를 기록합니다.
프로토타입에서 확인할 것
고객이 서비스가 무엇인지 10초 안에 이해하는가? 메뉴와 가격을 보고 신청 의향이 생기는가? 신청 버튼을 자연스럽게 찾는가?
MVP로 넘어가는 가장 현실적인 방법
화면에서 반응이 좋다면, 결제 시스템부터 만들기보다 카카오톡 채널·전화·간단한 신청 폼으로 10~20가구의 신청을 먼저 받아봅니다. 정해진 요일에 직접 배송하거나 기존 배송 수단을 활용해, 재주문 의향과 운영 부담을 확인합니다.
아직 만들지 않아도 되는 것
자동 결제, 배달 기사 배정, 개인화 추천, 리뷰 시스템, 고객용 앱입니다. 반복 주문과 운영 방식이 확인된 뒤에야 시간과 비용을 들여 개발할 이유가 생깁니다.
바이브코딩의 현실적인 범위
비개발자는 AI를 활용해 화면, 문구, 기본 흐름, 간단한 신청 페이지를 빠르게 만들고 수정할 수 있습니다. 다만 결제·개인정보·주문 데이터·배송 연동처럼 실제 운영에 영향을 주는 기능은 보안과 법적 책임이 따르므로 검증된 서비스나 개발자의 도움을 받아야 합니다.

② 구체적인 변경 내용 — 무엇을 어떻게 바꿀지 값까지 (예: X축은 ‘월’, Y축은 ‘매출(원)’)
③ 제약조건 — 반드시 지켜야 하는 조건 (예: 모바일에서는 카드 형태, 외부 서버 사용 안 함)

필요하면 HTML 파일로 저장해 내 컴퓨터에서 엽니다.

반응형(Responsive)이란?
하나의 웹페이지가 보는 화면의 크기에 맞춰 스스로 배치를 바꾸는 것을 말합니다. PC용 페이지와 모바일용 페이지를 따로 만드는 것이 아니라, 같은 파일이 넓은 화면에서는 여러 칸으로, 좁은 스마트폰 화면에서는 한 줄로 쌓이도록 만들어집니다.

비개발자에게는 낯선 확인 단계지만, 실제 고객의 상당수는 스마트폰으로 접속하므로 PC에서만 확인하고 끝내면 안 됩니다. 프롬프트에 “PC와 모바일에서 모두 보기 편한 화면”이라고 쓴 이유가 이것입니다.

쉽게 확인하는 방법
· 브라우저 창의 오른쪽 끝을 잡고 가로 폭을 좁혀보기
· (선택) 크롬에서 F12 → 휴대폰 모양 아이콘(기기 모드)을 눌러 스마트폰 화면으로 보기
· 배포 후에는 실제 스마트폰으로 URL에 접속해 확인하기

실습 B. 계산식이 동작하는 계산기 만들기

핵심 경험: 계산 로직을 자연어로 알려주면 단순한 화면뿐 아니라 실제로 값이 계산되는 기능도 만들 수 있습니다.

Chat에서 새 대화를 엽니다.
실습 A와 구분하기 위해 새 대화에서 시작합니다.
아래 프롬프트를 입력합니다.
입력 항목과 계산식을 빠뜨리지 않고 입력합니다. 계산식은 내가 정해서 알려주는 것이며, 이렇게 정한 계산식은 만들어진 계산기 안에서 절대 바뀌지 않고 그대로 동작합니다.
실습 B · 2단계 계산기 만들기
상품 가격 계산기 프로토타입을 만들어줘.

[입력]
- 상품 가격
- 구매 수량
- 할인율(%)

[계산식]
- 할인 전 금액 = 상품 가격 × 구매 수량
- 할인 금액 = 할인 전 금액 × 할인율 ÷ 100
- 최종 결제 금액 = 할인 전 금액 - 할인 금액

위 계산식은 그대로 사용하고 임의로 바꾸지 마.
입력창, 계산하기 버튼, 계산 결과가 보이는 화면으로 만들어줘.
정해진 계산식은 절대 바뀌지 않고 그대로 동작합니다.
ChatGPT에게 같은 질문을 하면 답변이 매번 조금씩 달라지지만, ChatGPT가 만든 계산기는 다릅니다. 계산기는 프롬프트에 적은 계산식을 코드로 옮겨 둔 것이므로, 같은 값을 넣으면 언제, 누가 사용해도 항상 같은 결과가 나옵니다. 계산할 때마다 AI가 새로 판단하는 것이 아닙니다.

그래서 계산식이 틀리면 틀린 결과가 계속 반복됩니다. 할인·수수료·세금처럼 돈과 관련된 계산식은 만들기 전에 사람이 먼저 확인하고, 이후 수정 요청을 할 때도 “기존 계산식은 변경하지 마”라고 금지조건을 적어 계산식이 바뀌지 않도록 지킵니다.
값을 입력해 계산 결과를 확인합니다.
직접 계산해 둔 값과 비교합니다. 예: 상품 가격 10,000원 · 수량 3개 · 할인율 10% → 할인 전 30,000원 / 할인 3,000원 / 최종 27,000원
오류 개선 방법: 캡처 → 첨부 → 설명
· 화면 캡처 — Windows: Win + Shift + S / Mac: Cmd + Shift + 4
· 캡처 이미지 첨부 — 캡처한 이미지를 입력창에 붙여넣거나(Ctrl/Cmd + V) 파일 첨부 버튼으로 올립니다.
· 설명 — “안 돼요”가 아니라 어디에서 · 무엇을 했더니 · 어떤 결과가 나왔고 · 원래는 어떻게 나와야 하는지를 적습니다.

말로만 설명하는 것보다 화면을 함께 보여주면 AI가 문제 위치를 훨씬 정확하게 찾습니다. 이 방법은 이후 홈페이지 실습에서도 그대로 사용합니다.
오류가 있으면 화면을 캡처해 AI에게 보여주고 고칠 부분을 설명합니다.
결과 금액이 틀리거나, 버튼이 동작하지 않거나, 글자가 겹쳐 보이면 해당 화면을 캡처합니다. 같은 대화 입력창에 캡처 이미지를 첨부하고, 무엇이 어떻게 잘못되었는지를 아래 형식으로 설명합니다.

[무엇을 했더니] 상품 가격 10000, 수량 3, 할인율 10을 입력하고 계산하기를 눌렀더니

저장 기능에서 알아둘 점

PRACTICE 02

2.3 홈페이지 프로토타입 만들기

대시보드·계산기·체크리스트 실습은 여기서 종료합니다. 이제 새 대화를 열고, 하나의 홈페이지를 처음부터 만들고 수정하는 실습을 시작합니다. 이 파트부터는 하나의 홈페이지 프로토타입을 계속 생성·수정합니다. 예시 프롬프트 안에서는 가상의 서비스명 ‘LocalLink’를 사용합니다.

용어를 모르는 상태에서도 일단 시작해보는 것이 의미가 있습니다.
HTML·CSS·JavaScript 같은 개발 용어를 처음부터 모두 알고 시작할 필요는 없습니다. 처음에는 누구를 위한 홈페이지인지, 어떤 내용이 필요한지, 어떤 버튼이 동작해야 하는지를 설명하는 것부터 시작합니다. 직접 만들고 고쳐보는 과정에서 각 용어가 화면의 어떤 부분을 가리키는지 자연스럽게 익히게 되고, 용어를 알게 될수록 AI에게 더 정확하게 요청할 수 있습니다. 용어는 시작의 조건이 아니라, 만들어보면서 따라오는 결과입니다.

2.4 (선택) HTML 파일의 특징 알아보기

2.3에서 저장한 index.html을 열어보며, 오늘 만든 결과물이 어떤 형태의 파일인지 간단히 이해합니다. 코드를 외울 필요는 없고, “이 파일은 이렇게 생겼구나”를 확인하는 것이 목표입니다.

1. 메모장으로도 열고 직접 수정할 수 있습니다

HTML 파일은 특별한 프로그램이 있어야 열리는 파일이 아니라, 글자로 이루어진 텍스트 파일입니다. 브라우저로 열면 화면이 보이고, 메모장 같은 텍스트 편집기로 열면 그 화면을 만드는 코드가 보입니다.

파일을 텍스트 편집기로 엽니다.
Windows: index.html 우클릭 → 연결 프로그램 → 메모장
Mac: 우클릭 → 다음으로 열기 → 텍스트 편집기 (코드 대신 화면처럼 보이면 텍스트 편집기 설정에서 ‘HTML 파일을 서식 있는 텍스트 대신 HTML 코드로 표시’를 체크한 뒤 다시 엽니다)
메인 제목 문구를 찾아 한 글자 바꿔봅니다.
Ctrl + F(Mac: Cmd + F)로 홈 화면의 제목 문구를 검색해 일부 글자를 수정합니다.
저장한 뒤 브라우저를 새로고침합니다.
바꾼 문구가 화면에 반영되면, AI 없이도 파일을 직접 고칠 수 있다는 것을 확인한 것입니다.
메모장으로 저장할 때 주의할 점
‘다른 이름으로 저장’을 할 때 파일 형식이 텍스트 문서(*.txt)로 되어 있으면 index.html.txt로 저장되어 브라우저에서 열리지 않습니다. 파일 형식은 모든 파일, 인코딩은 UTF-8로 저장합니다. 문구 수정이 아닌 기능 수정은 코드를 망가뜨리기 쉬우므로 AI에게 요청하는 편이 안전합니다.

2. 파일 이름은 .html 형식으로 끝납니다

파일 이름 뒤의 .html을 확장자라고 하며, 컴퓨터는 이 확장자를 보고 “브라우저로 여는 웹페이지 파일”이라고 판단합니다. 다만 Windows와 Mac은 기본 설정에서 확장자를 숨기는 경우가 많아, 파일 이름이 index로만 보일 수 있습니다.

구분확장자가 안 보일 때 설정 방법파일 아이콘
Windows 11파일 탐색기 → 보기 → 표시 → 파일 확장명 체크기본 브라우저(크롬·엣지·사파리 등)의 아이콘으로 표시
Windows 10파일 탐색기 → 보기 탭 → 파일 확장명 체크
MacFinder → 설정 → 고급 → 모든 파일 확장자 보기 체크

3. 코드는 <!DOCTYPE html>로 시작해서 </html>로 끝납니다

메모장으로 연 코드를 위에서 아래로 훑어보면, 대부분의 HTML 파일은 아래와 같은 공통된 뼈대를 갖고 있습니다.

예시 · index.html의 기본 구조
<!DOCTYPE html>              ← ① 시작: "이 파일은 HTML 문서입니다"라는 선언
<html lang="ko">             ← ② HTML 문서의 시작
  <head>                     ← ③ 화면에 보이지 않는 설정 영역
    <title>LocalLink</title>  (브라우저 탭에 보이는 제목, 디자인 설정 등)
    <style> ... </style>     (색상·글자 크기 같은 디자인)
  </head>
  <body>                     ← ④ 실제로 화면에 보이는 내용
    <h1>지역과 브랜드를 잇는 LocalLink</h1>
    ...
    <script> ... </script>   (버튼·메뉴 전환 같은 동작)
  </body>
</html>                      ← ⑤ 끝: HTML 문서가 여기서 닫힘
시작과 끝

<!DOCTYPE html> … </html>

파일의 첫 줄과 마지막 줄입니다. 대부분의 태그는 <이름>으로 열고 </이름>으로 닫습니다.

보이지 않는 영역

<head>

탭 제목, 글꼴, 색상 같은 설정이 들어갑니다. 화면 본문에는 나타나지 않습니다.

보이는 영역

<body>

메뉴, 제목, 버튼, 문의 폼처럼 실제 화면에 보이는 내용이 들어갑니다.

4. 인터넷이 없어도 열리고, 파일 그대로 공유할 수 있습니다

HTML 파일은 서버나 인터넷 연결 없이 내 컴퓨터의 브라우저만으로 열립니다. 이메일 첨부, USB, 사내 메신저, 공유 폴더 등으로 파일을 전달하면 받은 사람도 더블클릭만으로 같은 화면을 볼 수 있습니다. 별도 프로그램 설치나 회원가입도 필요 없습니다.

내부망(폐쇄망) 환경에서 특히 유용합니다
공공기관·지자체 공무원이나 대기업처럼 보안을 위해 외부 인터넷 서비스 연결이 막힌 내부망을 쓰는 곳에서는, 외부 웹사이트나 클라우드 도구를 사용하기 어렵습니다. 이런 환경에서도 HTML 파일은 파일만 옮기면 바로 열 수 있기 때문에, 외부 서비스에 연결하지 않고도 프로토타입 화면이나 간단한 계산기·대시보드·체크리스트를 공유하고 사용할 수 있습니다.
인터넷 없이 쓰려면 외부 연결이 없는 파일이어야 합니다
AI가 만든 HTML에는 그래프 라이브러리, 웹 글꼴, 아이콘처럼 인터넷에서 불러오는 요소가 들어 있는 경우가 많습니다. 이런 파일은 내부망에서 열면 그래프가 안 보이거나 글꼴·아이콘이 깨질 수 있습니다. 내부망에서 쓸 파일이라면 처음부터 아래처럼 요청합니다.
내부망에서도 열리는 HTML로 요청하기
인터넷이 연결되지 않은 내부망 PC에서도 열 수 있도록 만들어줘.

- 외부 라이브러리, 웹 글꼴, 외부 이미지, CDN 링크는 사용하지 마
- 그래프가 필요하면 외부 라이브러리 없이 직접 그려줘
- 필요한 디자인과 동작은 모두 index.html 한 파일 안에 넣어줘
- 외부 서버나 데이터베이스는 사용하지 마

확인 방법: 와이파이를 끄거나 랜선을 뺀 상태에서 파일을 열어 화면이 그대로 보이는지 확인합니다.

실전 팁: AI가 준 코드를 복사할 때
AI가 코드를 채팅창에 글로 보여준 경우, 첫 줄 <!DOCTYPE html>부터 마지막 줄 </html>까지 빠짐없이 복사해야 합니다. 답변이 중간에 끊겨 </html>이 없다면 “이어서 끝까지 작성해줘”라고 요청합니다.
여기까지는 아직 ‘배포’가 아닙니다.
브라우저에서 화면이 잘 열리더라도 파일이 내 컴퓨터에만 있다면 다른 사람은 접속할 수 없습니다. 다음 파트에서는 이 결과를 사이트 형태로 공유하거나, GitHub·Vercel을 이용해 실제 웹주소로 배포하는 흐름으로 이어집니다.
