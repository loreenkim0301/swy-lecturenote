SESSION 1 · 09:20–10:20

LLM이 무엇이고 어디서 틀리나

오늘 만드는 화면은 사용자의 감정을 AI가 읽고 책을 골라요. 먼저 그 AI, 곧 LLM이 무엇인지 알고, 책을 추천할 때 어디서 틀릴 수 있는지 직접 확인해요.

왜 하나?AI가 지어낸 책을 사용자가 사려고 누르면, 없는 상품 화면이 열려요. 기획자가 AI가 틀리는 곳을 알아야, 틀려도 사용자가 속지 않는 화면을 만들 수 있어요.

개념1-1. LLM이란?

LLM이란?

LLM(대규모 언어 모델)은 아주 많은 데이터로 학습한 언어 모델이에요. 글을 만들고, 번역하고, 요약하는 일을 해요. 클로드, 제미나이가 모두 LLM이에요.

어떤 문제를 해결하나요?

사용자는 감정을 "설레요", "좀 지쳤어요"처럼 저마다 다르게 적어요. 규칙으로 만들면 감정 낱말마다 책 목록을 미리 짝지어 둬야 해요. LLM은 처음 보는 표현도 뜻을 읽고 어울리는 답을 글로 만들어 줘요.

조심할 점

LLM은 사실과 다르거나 주어진 내용과 맞지 않는 글을 만들 수 있어요. 이것을 환각이라고 해요. 책 추천에서는 이런 모양으로 나타날 수 있어요.

틀릴 수 있는 곳예사용자에게 생기는 일
없는 책그럴듯한 제목을 지어냄검색해도 나오지 않아요
저자 바꿔 쓰기있는 책에 다른 저자 이름을 붙임다른 책을 사게 돼요
링크 지어내기상품 번호를 지어낸 주소없는 화면이나 엉뚱한 상품이 열려요

공식 문서는 환각을 줄이는 방법으로 "모르면 모른다고 말해도 된다고 허락하기", "근거를 함께 내게 하기"를 들어요. 2세션과 4세션에서 이 방법을 화면 기획에 써요.

링크가 열리지 않거나 다른 책이 열렸다면, 오늘 만드는 화면에서 같은 일이 생길 수 있다는 뜻이에요. 모두 맞았더라도 다음 사용자에게 또 맞는다는 보장은 없어요. 그래서 2세션에서 링크를 AI에게 맡기지 않는 방법을 기획해요.

SESSION 2 · 10:30–12:00

책 추천 화면 기획하기

1세션에서 본 문제를 화면 기획으로 막아요. AI에게 맡길 일과 코드가 할 일을 나누고, AI가 답할 모양을 정해요. 여기서 만든 기획표를 3세션 프롬프트에 그대로 넣어요.

왜 하나?AI가 아무리 좋아져도 틀릴 수 있어요. 그래서 기획자는 "틀리면 안 되는 값은 AI에게 맡기지 않는다"는 규칙을 화면 기획에 넣어요.

기획2-1. 링크는 AI가 아니라 코드가 만들기

검색 주소란?

검색 주소는 검색어가 주소 안에 들어 있는 링크예요. YES24에서 책을 검색하면 주소가 아래 모양이 돼요. query= 뒤가 검색어예요.

https://www.yes24.com/product/search?domain=BOOK&query=어린왕자

어떤 문제를 해결하나요?

상품 페이지 주소에는 상품마다 다른 번호가 들어가요. AI가 이 번호를 지어내면 엉뚱한 화면이 열려요. 검색 주소는 번호가 필요 없어요. 코드가 책 제목을 query= 뒤에 붙이기만 하면 돼요. 책이 정말 없다면 검색 결과가 비어 보여서, 사용자도 바로 알아요.

누가하는 일
AI(제미나이)감정을 읽고 책 제목·저자·추천 이유를 고르기
코드제목으로 YES24 검색 주소 만들기, 카드에 나눠 넣기
사용자[YES24에서 보기]를 눌러 실제 책을 확인하고 고르기

이번 실습에서는 새로운 코드가 하나 나와요

코드하는 일
encodeURIComponent(제목)한글이나 띄어쓰기가 든 제목을 주소에 넣을 수 있는 글자로 바꿔요. AI 스튜디오가 이 코드를 넣어 줘요.

조심할 점

화요일에 YES24 robots.txt를 읽었던 것 기억하시나요? 오늘 앱은 YES24 페이지를 모으지 않아요. 사용자가 누를 링크만 만들어요.

출처: YES24 검색 화면 '어린왕자' 검색 결과 · MDN encodeURIComponent() (2026.11.08 확인)

STEP 1. 검색 주소를 직접 열어 보기

크롬 주소창에 위 주소를 넣어 열어요. 그다음 query= 뒤를 좋아하는 책 제목으로 바꿔서 다시 열어 봐요. 검색 결과에 그 책이 보이는지 봐요.

  • '어린왕자' 검색 결과 화면이 열린다
  • 제목만 바꿔도 다른 책의 검색 결과가 열린다

기획2-2. AI에게 받을 답의 모양 정하기

JSON으로 받는 이유

AI가 긴 글로 답하면 코드는 어디가 제목이고 어디가 저자인지 알 수 없어요. 칸 이름을 정해 JSON으로 받으면, 코드가 칸마다 꺼내 카드에 넣어요.

예시AI가 돌려줄 답의 모양

  {"title": "…", "author": "…", "reason": "…"},
  {"title": "…", "author": "…", "reason": "…"}
]}

왜 하나?금요일에는 우리가 직접 API 키를 받아 챗봇에 붙여요. AI 스튜디오가 키를 어떻게 숨겨 두는지 알면, 금요일에 같은 방법으로 키를 지킬 수 있어요.

개념5-1. AI 스튜디오 앱이 제미나이를 부르는 길

API 키는 어디에 있나요?

AI 스튜디오 Build로 만든 웹 앱은 내 제미나이 API 키를 써요. AI 스튜디오가 이 키를 앱의 서버 쪽에 비밀값(Secret)으로 넣어 둬요. 키는 사용자가 보는 화면 코드에 들어가지 않아요. 그래서 앱을 공유받은 사람도 내 키를 볼 수 없어요.

1사용자 화면감정 입력, [책 추천받기]
2앱의 서버비밀값으로 둔 API 키
3제미나이 API책 3권 JSON
4앱의 서버답을 화면으로 전달
5사용자 화면카드 3장

무료로 얼마나 쓸 수 있나요?

항목공식 문서 내용
처음 등급새 계정은 무료 등급(Free Tier)으로 시작해요. 무료 등급에서 쓸 수 있는 모델과 한도가 정해져 있어요.
무료 모델 예가격표에서 gemini-3.8-flash의 무료 등급 입력·출력 가격은 'Free of charge'예요.
한도의 단위분당 요청 수(RPM), 분당 토큰 수(TPM), 하루 요청 수(RPD). 한도는 API 키가 아니라 프로젝트마다 적용돼요. 내 한도는 AI 스튜디오에서 볼 수 있어요.
하루 한도가 다시 차는 때미국 태평양 시간 자정이에요. 11월에는 한국 시간 오후 5시예요.
공유한 앱다른 사람이 내 앱을 쓰면, 그 호출도 내 사용량에 쌓여요. 유료 모델을 쓰면 요금이 생길 수 있어요.
무료 등급의 데이터가격표에 무료 등급은 '제품 개선에 사용됨(Used to improve our products: Yes)'으로 적혀 있어요. 그래서 입력칸에 개인정보를 넣지 않아요.
