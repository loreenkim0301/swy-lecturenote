SESSION 1 · 09:20–10:00

실험 준비: 키와 측정 규칙

오늘은 클로드 API 키와 제미나이 API 키를 함께 써요. 두 키 모두 유료 키이고, 수업이 끝나면 지워져요.

왜 하나?키가 깃헙에 한 번 올라가면 누구나 쓸 수 있어요. 여러 팀이 같은 키를 쓰는 날일수록 키를 다루는 규칙을 먼저 지켜야 해요.

개발자·구현1-1. API 키를 .env에 넣기

4주차 월요일에 상담 챗봇의 .env 파일에 API 키를 넣었던 것 기억하시나요? 오늘도 같은 파일에 키를 넣어요. 클로드 코드에 아래 프롬프트를 먼저 보내고, 키는 클로드 코드가 만든 .env 파일을 열어 직접 붙여 넣어요. 키를 채팅 입력창에 붙여 넣지 않아요.

프롬프트 1 · 클로드 코드에 붙여 넣으세요
요청: 오늘 실험에 쓸 키 자리를 .env 파일에 만들어 줘.
내용: ANTHROPIC_API_KEY와 GEMINI_API_KEY 두 줄을 만들고 값은 비워 둬. .gitignore에 .env가 들어 있는지 확인하고, 없으면 넣어 줘. 지금 깃헙에 올라갈 파일 목록에 .env가 없는지도 보여 줘.
형식: ① .env 줄 목록(값 없이) ② .gitignore 확인 결과 ③ 올라갈 파일 목록

이렇게 보이면 성공.env에 키 두 개가 들어 있고, 올라갈 파일 목록에 .env가 없어요.

키가 올라가면

GitHub는 2026년 10월부터 Anthropic 키가 담긴 푸시를 기본으로 막아요. 하지만 다른 키는 막히지 않을 수 있어요. 키가 올라갔다고 생각되면 바로 강사에게 알려요. 키를 지우고 새로 받아야 해요.

출처: GitHub Secret scanning blocks Anthropic keys by default (2026-11-20 확인)

규칙1-2. 측정 시간과 규칙

여러 팀이 같은 키로 동시에 평가 프로그램을 돌리면 API의 분당 한도에 걸릴 수 있어요. 그러면 'AI가 느리다'가 아니라 '한도에 걸렸다'가 결과가 돼요. 그래서 측정은 팀마다 정해진 시간에 해요.

규칙이유
측정은 우리 팀 시간에만 돌려요다른 팀과 한도를 나눠 쓰지 않게 해요
한도 초과 오류는 '오류'로 따로 적어요느린 답과 섞이면 속도 비교가 틀어져요
측정 중에는 같은 키로 다른 실습을 하지 않아요측정 기록에 다른 요청이 섞이지 않게 해요

출처: Claude 문서 Rate limits(분당 요청 수, 분당 입력·출력 토큰으로 한도를 잼) (2026-11-20 확인)

대조군 재기: 낱말 검색 챗봇

4주차 월요일에 만든 챗봇은 질문의 낱말과 같은 뜻 낱말 묶음으로 FAQ를 골라요. 이 챗봇이 오늘의 기준이에요. 먼저 이 챗봇의 점수를 재요.

왜 하나?기준을 재지 않으면 새 방법이 나아졌는지 말할 수 없어요.

기획자2-1. 대조군과 평가 질문 15개

4주차 월요일에 만든 시험지는 챗봇이 규칙을 지키는지 보는 문항이었어요. 오늘 평가 질문은 찾는 방법을 비교하려고 세 종류로 나눠 만들었어요.

개발자·구현2-2. 평가 프로그램 만들기

질문 15개를 사람이 하나씩 보내고 시간을 재면 오래 걸리고 틀리기 쉬워요. 평가 프로그램이 질문을 보내고 기록하게 해요. 이 프로그램은 실험 1·2에서도 그대로 써요.

프롬프트 2 · 클로드 코드에 붙여 넣으세요
요청: 상담 챗봇의 찾기·답하기 방법을 비교하는 평가 프로그램을 만들어 줘.
내용: data/questions.csv의 질문 15개를 차례로 보내. 지금 챗봇의 낱말 검색은 지우지 말고 '낱말 검색 + 클로드' 조건으로 이름 붙여 둬. 질문마다 조건 이름, 질문 번호, 찾은 FAQ 번호 3개(18|14|19처럼 | 로 이어 한 칸에), 찾는 시간(초), 답하는 시간(초), 입력 토큰, 출력 토큰, 임베딩 토큰(없으면 0), 답 내용, 오류 내용을 이 순서대로 data/results.csv에 한 줄씩 더해. 첫 번째 요청은 준비 운동으로 보고 기록에서 빼. temperature는 0으로 맞춰. 키는 .env에서만 읽고, 키가 results.csv나 코드에 들어가지 않게 해.
형식: ① 실행 명령 한 줄 ② results.csv 칸 이름 목록 ③ '낱말 검색 + 클로드' 조건으로 질문 1번만 돌린 결과

이렇게 보이면 성공results.csv에 질문 1번 한 줄이 생기고, 찾는 시간·답하는 시간·토큰 칸이 모두 채워져 있어요.

막히면이렇게 해요
토큰 칸이 비어 있어요클로드 코드에게 "API 응답의 usage에서 input_tokens와 output_tokens를 읽어 줘"라고 해요.
찾는 시간과 답하는 시간이 한 칸에 합쳐져 있어요"FAQ를 고르는 부분과 AI에게 보내는 부분의 시간을 따로 재 줘"라고 해요.

출처: Claude 문서 Cost tracking(응답의 usage에 input_tokens·output_tokens가 담김) · Gemini API 문서 Counting tokens(응답의 usageMetadata에 promptTokenCount·candidatesTokenCount가 담김) (2026-11-20 확인)

개발자·구현3-2. 파이어스토어에 FAQ와 좌표 넣기

이번 실습에서는 새로운 말이 몇 가지 나와요. 임베딩은 글의 뜻을 숫자 목록(좌표)으로 바꾸는 일이고, 그 숫자의 개수를 차원이라고 불러요. 제미나이 임베딩 모델은 기본으로 3,072차원 좌표를 만들어요. 그런데 파이어스토어에 좌표를 넣을 때는 2,048차원으로 맞추는 것이 중요해요. 그래서 프롬프트에 차원을 적어 줘요.
