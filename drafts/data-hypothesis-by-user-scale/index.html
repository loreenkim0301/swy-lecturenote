사용자 수에 맞는 방법으로 가설을 검증해요

A/B 테스트는 사람이 충분히 모여야 판정할 수 있어요. 사람이 적은 초기에는 사람을 직접 만나고, 손으로 해 주는 방법으로 먼저 확인해요. 수학적인 통계 분석은 제품이 자라 사용자가 꾸준히 들어온 뒤에 쓰는 나중 단계의 도구예요. 오늘은 사용자 수를 다섯 단계로 나눠 단계마다 맞는 검증 방법을 보고, 필요한 인원을 직접 계산해 봐요.

일정과정에 맞춰 정해요(약 3시간 분량)
준비물크롬, 클로드, 계산기 또는 구글 시트
오늘의 결과물내 서비스의 단계 판단표 + 필요한 인원 계산 + 내 가설의 검증 계획

SESSION 1 · 50분

사용자 수에 따라 검증 방법이 달라요

사용자가 10명일 때와 1만 명일 때는 같은 방법으로 가설을 확인할 수 없어요. 사용자 수를 다섯 단계로 나눠 단계마다 무엇을 묻고 어떻게 확인하는지 봐요.

왜 하나?사람이 적은데 A/B 테스트부터 하면 몇 달을 기다려도 '판정할 수 없음'으로 끝나요. 지금 단계에 맞는 방법을 골라야 빨리 배울 수 있어요.

개념1-1. 가설 검증과 A/B 테스트

가설 검증이란?

초기 프로덕트는 "이 기능을 만들면 사용자가 이렇게 행동할 것이다"라는 가설에서 시작해요. 그래서 작게 만들어 내보내고, 사용자의 반응을 재고, 그 결과로 다음에 할 일을 정해요. 에릭 리스는 『린 스타트업』에서 이 과정을 만들기 → 재기 → 배우기(Build–Measure–Learn)라고 불렀어요.

A/B 테스트란?

방문자를 무작위로 두 무리로 나눠 한쪽에는 지금 화면(A), 다른 쪽에는 바꾼 화면(B)을 같은 기간에 보여 주고, 미리 정한 지표로 견주는 실험이에요. 같은 기간에 견주기 때문에 요일·날씨·광고 같은 다른 영향을 줄일 수 있어요.

조심할 점

A/B 테스트는 사람이 충분히 모여야 판정할 수 있어요. 사람이 적으면 두 안의 차이가 진짜인지 우연인지 가릴 수 없어요. 몇 명이 필요한지는 세션 2에서 계산해요.

출처: Lean Startup Co. 원칙 (2026.11.09 확인)

조심할 점

사례1-3. 초기 기업은 기술 없이 먼저 확인했어요

회사무엇을 했나결과출처
드롭박스 (1단계)비공개 베타를 소개하는 영상을 올렸어요. 영상에는 제품이 어떻게 작동할지 담았어요2008년 3월, 베타 대기자가 하루 만에 5,000명에서 75,000명으로 늘었어요. 제품 사용자 없이 수요부터 확인한 거예요창업자 드루 휴스턴 발표 자료(2010) · 위키백과 Timeline of Dropbox
자포스 (2단계)창업자가 동네 신발 가게에 "사진을 찍어 온라인에 올리고, 주문이 들어오면 정가로 사 가겠다"고 제안했어요1999년, 재고 없이 주문 몇 건을 받아 '사람들이 온라인으로 신발을 살까'를 확인했어요Fortune 2012 · Alexander Jarvis
버퍼 (2단계)설명 페이지 → 가격 플랜 페이지 → 이메일 남기기 순서의 페이지만 만들었어요. 제품은 없었어요. 사람들이 어떤 플랜을 누르는지로 가격을 확인했어요제품을 7주 만에 만들고, 출시 4일 안에 첫 유료 고객이 생겼어요. 2개월 반 뒤 사용자 500명이 넘었고, 약 4%가 유료로 바꿨어요버퍼 공식 블로그(창업자 조엘 개스코인)
에어비앤비 (3단계)2009년, 뉴욕 숙소 약 40곳의 사진이 나쁘다는 것을 보고 창업자들이 직접 가서 사진을 다시 찍었어요주간 매출이 200달러에서 1주 뒤 400달러로 두 배가 됐어요. 데이터 없이 시작한 전·후 비교였고, 나눠 보여 주는 A/B 테스트는 아니었어요First Round Review(공동창업자 조 게비아 인터뷰)

네 사례 모두 통계 도구를 쓰지 않았어요. 사람이 적을 때는 "기술 없이 손으로 해 줬을 때 사용자가 반응하는가"를 먼저 봐요. 버퍼도 페이지를 나눠 보여 주지 않고, 가격 페이지를 중간에 끼워 넣어 순서대로 확인했어요.

SESSION 2 · 50분

몇 명이 있어야 판정할 수 있나요

정통 통계에서는 A/B 테스트를 시작하기 전에 몇 명이 필요한지 먼저 계산해요. 공식을 한 번 보고, 셀렉트마켓 숫자로 직접 계산해요.

왜 하나?필요한 인원을 모르고 시작하면, 판정할 수 없는 실험에 몇 달을 쓰거나 좋아 보일 때 멈춰 틀린 결론을 내요.

개념2-1. 표본 수란?

표본 수란?

A/B 테스트에서 두 안의 차이를 판정하려면 필요한 사람 수예요. 계산하려면 네 가지를 먼저 정해요.

정할 것뜻보통 쓰는 값
기준 전환율(p₁)지금 화면(A)의 전환율내 서비스의 실제 숫자
최소 감지 효과(MDE)"이 정도 차이는 잡아내고 싶다"는 크기비즈니스에서 의미 있는 차이
유의수준(α)효과가 없는데 있다고 잘못 판정할 확률을 어디까지 받아들일지5%
검정력(1−β)효과가 진짜 있을 때 잡아낼 확률80%

어떤 문제를 해결하나요?

"일주일 돌려 보고 정하자"처럼 감으로 기간을 정하면, 사람이 모자라 판정할 수 없거나 우연을 효과로 착각해요. 표본 수를 먼저 계산하면 "이 실험은 언제까지, 몇 명을 보고 정한다"를 미리 약속할 수 있어요.

개념2-2. 공식으로 필요한 인원 구하기

두 비율을 견주는 공식은 아래와 같아요. p₂는 B안의 목표 전환율이에요.

그룹당 인원 n = (1.96 + 0.84)² × [p₁(1−p₁) + p₂(1−p₂)] ÷ (p₂ − p₁)²
               (유의수준 5% 양측, 검정력 80%일 때)

지금 전환율이 10%라고 하고 공식에 넣으면 아래와 같아요.

B안 목표 전환율지금보다그룹당 인원A·B 합계해당 단계
17.6%76% 개선319명약 640명3단계
15%50% 개선683명약 1,400명3~4단계

조심할 점

위 표의 인원은 정해진 기준이 아니라 계산 결과예요. 지금 전환율과 잡고 싶은 차이가 바뀌면 필요한 인원도 바뀌어요.

출처: 표는 위 공식에 값을 넣어 계산 · Evan Miller 표본 수 계산기 (2026.11.10 확인)

사례2-3. 월 사용자가 1,000명이라면

전환율 10%인 페이지에서 한 달 동안 1,000명을 500명씩 나눠 보여 준다고 해 봐요. 공식에 넣으면 약 5.9%p 넘게 차이가 나야 판정할 수 있어요. B안 전환율이 16%쯤(약 60% 개선)은 되어야 한다는 뜻이에요. B안이 13%(30% 개선)로 꽤 좋아도 '판정할 수 없음'이 돼요.

그래서 월 사용자가 1,000명 수준이면 버튼 색이나 문구 하나를 바꾸는 A/B 테스트는 하지 않아요. '무료 유지 vs 유료 플랜 도입'처럼 반응이 크게 갈릴 제안을 견주거나, 세션 3의 방법을 써요.

SESSION 3 · 50분

사람이 적을 때와 많을 때의 검증

세션 2에서 사람이 모자라다는 것을 확인했다면 무엇을 해야 할까요? 사람이 적을 때 쓰는 방법과, 사람이 많아진 뒤 정통 통계를 쓰는 모습을 보고 내 검증 계획을 써요.

왜 하나?사람이 적다고 검증을 미루면 감으로 만들게 돼요. 지금 쓸 수 있는 방법이 따로 있어요.

개념3-1. 사람이 적을 때 쓰는 방법 5가지

방법이렇게 해요근거
사용성 테스트사용자 5명이 직접 써 보는 모습을 보고 문제를 찾아요. 한 번에 15명보다, 5명씩 세 번 테스트하고 그 사이에 고치는 편이 나아요제이콥 닐슨: 5명이면 사용성 문제의 약 85%를 찾아요(2000). 숫자로 비교하는 정량 연구는 20명을 권해요
크게 바꾸기문구 하나가 아니라 제안 자체를 바꿔요. 예: 무료 유지 vs 유료 플랜 도입Optimizely: 트래픽이 적으면 영향이 큰 변화를 테스트
작은 행동 재기(마이크로 전환)결제 완료 대신 장바구니 담기, 30초 머물기처럼 더 자주 일어나는 행동을 지표로 써요Optimizely: 결과를 더 빨리 판정할 수 있음
여러 안 동시에 하지 않기A·B 두 안만 비교해요. 여러 요소를 한 번에 섞는 다변량 테스트는 트래픽이 충분해질 때까지 미뤄요Optimizely: 변형이 많을수록 트래픽이 더 필요
바로 적용하고 지켜보기개선이 뚜렷하면 바로 적용하고 전·후 숫자를 지켜봐요. 전·후 비교는 요일·광고 영향이 섞이므로, 그 기간에 있었던 일을 함께 적어 둬요에어비앤비 사진 사례(1-3)

조심할 점

A안을 이번 주, B안을 다음 주에 보여 주는 전·후 비교는 A/B 테스트가 아니에요. 숫자가 바뀌어도 요일·날씨·광고 때문인지 알 수 없어서 참고용으로만 써요.

사례3-2. 정통 통계가 주력이 될 때

사용자가 수만 명 이상 꾸준히 들어오면, 10~20%의 작은 개선도 통계로 판정할 수 있어요. 이때부터는 실험을 여러 팀이 동시에 돌리고, 새 기능을 조금씩 넓혀 배포해요.

넷플릭스작품 이미지를 회원들에게 나눠 보여 주고, 노출 대비 재생 비율(take rate)로 이긴 이미지를 골랐어요(2016)Netflix Tech Blog

메타(페이스북)새 코드를 직원에게 먼저 내보내고, 다음에 실제 사용자의 2%, 마지막에 100%로 넓혀요. 기능은 게이트키퍼(Gatekeeper)라는 스위치로 켜고 꺼요Meta Engineering(2017)

조심할 점

  • 결과를 자주 들여다보다가 좋아 보일 때 멈추면 잘못 판정할 확률이 올라가요. 에반 밀러의 예에서는 5%로 정해 두었던 오판 확률이 26.1%까지 올라갔어요. 필요한 인원을 미리 정하고 그때까지 기다려요.
  • '순차 검정(sequential testing)'은 A안 2주 → B안 2주처럼 기간을 나눠 보여 주는 것이 아니에요. 동시에 나눠 보여 주면서 중간 확인을 허용하는 통계 방법이에요.
